## 性能分析（analyzing-dotnet-performance）
- 项目：IPTVLiveChecker，目标框架 **net472**（WinForms + LibVLCSharp）。
- 结论：核心检测引擎设计合理（共享单 HttpClient + SemaphoreSlim 限流 + 流式 ResponseHeadersRead + HashSet 去重）。
- 主要问题（均 Moderate，无 Critical）：
  - M1 检测循环对 buf 重复 `Encoding.UTF8.GetString` 全量解码（15835/16125/16370）
  - M2 约 10 处每调用 `new Regex`/`Regex.Matches`，应提升 static readonly + Compiled
  - M3 热路径 `IndexOf/Contains(string)` 缺 StringComparison（net472 默认 CurrentCulture）
  - M4 `allChannels.Any(c=>c.Url==url)` 在循环内 O(n) → O(n²) 去重（14 处）
  - M5 范围扫描器 `new HttpClient()` 未设 MaxConnectionsPerServer（net472 默认每服务器 2 连接，吞吐瓶颈）
  - M6 17 处 `ToLower()` 应改 `ToLowerInvariant()`
- 报告已保存：`IPTVLiveChecker/性能分析报告.md`
- 用户偏好：要求先做错误前提/逻辑核查、独立判断、区分事实与推测（见自定义指令）。

## WebView2 白屏修复
- 现象：Web 窗口能打开但内容空白、无任何报错。
- 确诊（源码审查，非运行验证，因沙箱是 Linux 无法跑 GUI）：
  - 根因1（确定缺陷）：`WebView2InitCompletedHandler`(L5288) **未检查 `IsSuccess`**；WebView2 内核初始化失败时 `CoreWebView2` 为 null 且静默 return。而 `EnsureCoreWebView2Async()` 失败时**不抛异常**（失败信息仅在事件参数里），导致 `dlg.Load` 中对 null 内核设置 `Source` 被静默丢弃 → 白屏无提示。最常见触发：本机未装/被禁用 Edge WebView2 Runtime（`IsWebView2Supported` 只查 Edge 浏览器/loader/注册表，不保证 `EnsureCoreWebView2Async` 成功）。
  - 根因2（代码质量）：导航双路径竞争——事件处理器 `core.Navigate` 与 `Load` 里 `Source=` 各触发一次。
  - 次要假设（需本机验证，非代码缺陷）：窗体 `SetRoundedRegion()` 非矩形 Region 可能在部分 WebView2 版本干扰其合成层渲染。
- 修复（已 `dotnet build -p:OutputPath=bin/Verify/` 验证 **0 警告 0 错误**）：
  - `WebView2InitCompletedHandler`：反射读取 `IsSuccess`/`InitializationException`，失败时显式弹错误提示（不再静默）。
  - `dlg.Load`：await 后统一在 `CoreWebView2 != null` 时导航（优先 `CoreWebView2.Navigate`，兜底 `Source`），移除非事件处理器里的重复导航；内核为 null 时只清理待导航标记、由 Init 处理器报错。
- 运行时仍需用户在本机 Windows 双击 exe 验证；若修复后仍有白屏，先排查 WebView2 Runtime 是否安装，再临时注释 `SetRoundedRegion()` 验证圆角 Region 是否干扰渲染。

## 启动窗口未圆角（回归修复）
- 现象：软件启动（主窗口）默认未显示圆角；拖拽改变大小后（ResizeEnd）又恢复正常。
- 根因（定位准确）：上一轮把主窗体 `base.Resize`→`base.ResizeEnd` 以消除拖拽顿挫。但启动初期 WinForms 在 `HandleCreated` 之后会用最终尺寸/`CenterScreen` 定位再触发一次初始 `Resize`；**原来**那次 `Resize` 会用最终尺寸重跑 `ApplyWindowShape()` 纠正形状，**改后**该纠正不再发生 → `HandleCreated` 时按未定稿尺寸建的 `Region` 圆角失效。同理最大化/还原只触发 `Resize` 不触发 `ResizeEnd`，会导致最大化后残留旧 `Region` 把窗口裁掉（潜在回归）。
- 修复（已编译验证 0 警告 0 错误）：
  - 在 `IPTVLiveCheckerMain_Load` 末尾（BuildUI 之后）加一次 `ApplyWindowShape()`，作为启动定型后纠正（等价原初始 `Resize` 纠正，但只跑一次、无 per-tick 成本）。
  - 新增字段 `_lastWindowState`；`base.Resize` 改为**仅当 WindowState 变化**时调 `ApplyWindowShape()`（廉价比较，无 GDI+ 每 tick 分配 → 不引入顿挫），覆盖最大化/还原；拖拽仍由 `base.ResizeEnd` 在松手时重建圆角。
  - 形状定义：`_windowRadius=10`（L766），`ApplyWindowShape` 同时设 DWM 圆角(属性33)与 GDI+ `Region` 裁剪 + `_borderOverlay` 1px 描边。
