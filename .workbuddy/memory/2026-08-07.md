2. 重写 `LayoutStatusBar()`：

## 第十三次整理：修复 statusBarRef.Paint 局部函数编译错误（CS0103 / 参数类型不匹配误报）

用户反馈编译错误：参数 5 无法从 int 转 Color、参数 4 无法从 int 转 Point。用 `dotnet build -c Release` 取到真实错误：`CS0103: 当前上下文中不存在名称"textY"`（IPTVLiveCheckerMain.cs L22544）。

根因（事实）：进度条 `statusBarRef.Paint += delegate { ... }` 内定义了三个局部函数 `Measure / OverFill / DrawAt`。**C# 规定：定义在匿名方法（delegate/lambda）内部的局部函数无法捕获该匿名方法的局部变量**（如 `textY`、`w`、`h`），只能引用参数与类字段。**原 `DrawAt` 直接引用外围 `textY`，编译器报 CS0103；IDE 因无法解析 `textY`，对内部 `TextRenderer.DrawText` 调用连带误报"参数4(int→Point)/参数5(int→Color)类型不匹配"**——真正的错是名字解析失败，不是参数本身写错。注：磁盘上该局部函数体曾被 VS（PID 25596）调试实例覆盖成 `new Rectangle(x, 0, w, h)`，但 `w`/`h` 同样是匿名方法局部变量，根因完全一致。

修复（IPTVLiveCheckerMain.cs，仍因 VS 持续改写用 Python 脚本按 token 精确替换）：
1. `Measure` 增加参数 `(Graphics g, int maxW, int hh)`，体内改用传入的 `g / maxW / hh`，不再引用 `e.Graphics / w / h`。
2. `DrawAt` 增加参数 `(Graphics g, int hh)`，体内 `int ty = Math.Max(0, (hh - f.Height) / 2)` 手动垂直居中，用 `new Point(x, ty)` 绘制，不再引用 `textY / w / h`。
3. `OverFill` 保留，仅引用类字段 `progressBarWidth`（字段可捕获，安全）。
4. 所有调用点显式传入 `e.Graphics, ..., w, h`：用括号配对算法批量重写 `Measure(...)`（2参→5参）与 `DrawAt(...)`（4参→6参），正确处理 `OverFill(...)` 嵌套括号。

验证：`dotnet build -c Release` → 0 警告 0 错误，产物 `bin/Release/net472/IPTVLiveChecker.exe`（838735 字节）。临时脚本 `_fix_paint.py` 已清理。

环境提醒（重申）：VS 调试实例（PID 25596）仍在运行，会持续锁定 `bin/Debug` 并可能覆盖源码。建议测试前关闭该调试实例，直接用 Release exe 验证；否则 VS 可能再次回退本次修复。
