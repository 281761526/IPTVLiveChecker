## 主题切换刷新机制同步性分析
- 用户问"切换主题界面窗口刷新机制是否同步"，逐行核查了 `SetTheme`→`ApplyTheme` 完整调用链。
- **SetTheme (L16626)**：`_applyingTheme` 重入守卫 → `MakeEffectiveTheme()` → `ApplyTheme()` → `channelPlayer?.ApplyTheme(theme)` → `ApplyWebViewNavTheme()`。
- **ApplyTheme (L16065)**：`SuspendLayout` → 全量重绘主窗（标题栏/工具栏/数据网格/状态栏/滚动条/菜单/导航按钮/搜索框/ComboBox…）→ `ApplyGlassFx()` + `ThemeFx.ApplyThemeFx(this, theme)` → **再次**调 `channelPlayer?.ApplyTheme` + `ApplyWebViewNavTheme` → `ResumeLayout` + 6 个关键面板 `Invalidate`。
- **结论：全部同步、同一线程、无异步**。`ApplyTheme` 内 `SuspendLayout/ResumeLayout` 保证原子性；所有子窗口（ChannelPlayer/WebView2）在同一调用栈内同步刷新；模态对话框用完即弃不存在同步问题。
- **发现两个可优化点**：
  1. `channelPlayer?.ApplyTheme` 和 `ApplyWebViewNavTheme` 在 `SetTheme` 和 `ApplyTheme` 末尾**重复调用**（L16269-16271 + L16638-16640），功能无碍但冗余。
  2. `SystemEvents.UserPreferenceChanged`（L16054，"跟随系统"模式）直接调 `ApplyTheme()` 不经 `SetTheme`，但 `ApplyTheme` 末尾已包含子窗口刷新，所以仍同步——无 bug。
