修复直播源窗口 · 现代风格设计方案

先基于现有代码做事实分析，再给出 3 款可直接落地的可视化界面设计，供你选择。

一、现状分析（代码事实 vs 我的判断）
代码事实

当前窗口构成（ShowReplaceUrlDialog）

  • 固定 480×320 对话框，绝对像素布局（Location/Size 手写坐标）。
  • 标题为整句："将可用IP+端口或网址替换为新地址"。
  • 字段：原始地址(只读框)、新IP/域名、新端口、预览(只读框，由 protocol+host+port+path 拼接)。
  • 按钮：确定 / 取消（均为 outline 描边样式，无主次）。
  • 逻辑：输入时实时拼接预览；输入 "ip:port" 自动拆分；确定后改 ch.Url 并重置状态。
  • 字体偏小（7.5f / 7f），纯文本无图标、无分组、无语法高亮。
可改进点（建议，非事实）

体验与视觉上的短板

  • 校验滞后：仅点"确定"才提示"IP/域名不能为空"，应在输入时实时校验。
  • 信息冗余：原始地址 + 预览两个只读框，预览本质上就是"新地址"，可合并为带差异高亮的单一结果。
  • 无主次按钮：确定/取消同权，关键操作不突出。
  • 无语法高亮：URL 是一长串，protocol / host / path 混在一起难读。
  • 标题冗长：可凝练为"修复直播源地址"。
  • 绝对坐标布局在极端 DPI 下仍偏挤，建议改用流式/锚定布局。

风格：居中卡片 + 毛玻璃背景 + 顶部蓝色高光描边，输入框改为胶囊形。
  • 柔和、轻盈，最"现代感"。
  • 实时结果用胶囊 chip 呈现，圆角统一。
  • 主次按钮分明（确定为蓝色实心胶囊）。
方案 B · Fluent 分栏高亮侧边强调条 + 语法高亮结果
推荐

风格：左侧 4px 蓝色强调条 + 标签大写字母、结果区做 语法高亮（protocol 灰、host 蓝）。
  • 层级清晰、信息密度高，最贴合工具类软件。
  • URL 分段着色，一眼看懂哪段被改。
  • 主按钮文案"确定替换"更明确。
方案 C · 行内编辑 + 差异就地改 URL · 变更红绿对比

风格：把整条 URL 当作可编辑行，仅 host:port 段高亮可改，path 锁定；下方用 红绿差异展示变更。
  • 最贴近"所见即所得"，改哪看哪。
  • 差异对比直观，降低误操作。
  • 一步到位，无需先填原始再填新值。
